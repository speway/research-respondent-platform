# Банк респондентов: накопление и передача агенту

В `/cabinet` сохраняются исходные файлы и отдельные версии результата. Банк
использует существующее закрытое хранилище и импортёр; старые проекты и ключи
продолжают ссылаться на прежние файлы. Реляционная миграция этим не завершается.

## Подготовка данных

Базы: CSV UTF-8, TSV или плоский JSON (массив объектов либо `{records: [...]}`).
Вложенные объекты/массивы в ячейках не поддерживаются. Множественный ответ —
строка с JSON-массивом буквальных вариантов, как требует существующий исполнитель.
Каждый вопрос — отдельный уникальный заголовок, удобнее точная формулировка с
разделом. XLSX сначала экспортируется в CSV UTF-8. Лимиты исходника и результата:
2 МиБ, 5000 записей, 250000 ячеек, 2000 столбцов. JSON результата иногда больше
CSV исходника; слишком большой результат не сохраняется.

Постоянный `participant_id` связывает человека между исследованиями. Для
повторных прохождений нужен `response_id` (либо иной документированный ключ).
Идентификаторы сопоставляются точно: ведущие нули сохраняются, пробелы по краям,
пропуски и булевы значения в ключах блокируют операцию. ID не выводятся из имени,
телефона или описания личности. Глобальная уникальность ID между независимыми
исследованиями остаётся обязанностью владельца: автоматическое распознавание
одного человека в разных источниках не реализовано.

Шаблоны `/bank-templates/participants.csv` и `/bank-templates/answers.csv` содержат
только заголовки, без записей. В шаблон ответов нужно добавить столбцы пунктов
конкретной методики. Исходные ответы сохраняются отдельно от производных шкал.
Сведения о разрешении/согласии в файле не заменяют проверенное доказательство и
не дают разрешения на внешнюю отправку.

## Пополнить базу

1. Загрузить сохранённую базу и файл дополнения с описанием источника/прав.
2. В «Банк респондентов» выбрать «Пополнить базу» и ID в обоих файлах.
3. При повторных прохождениях добавить `response_id` к ключу. API допускает два
   дополнительных столбца, интерфейс сейчас один.
4. Указать название/версию результата и основание его использования; проверить.
5. После проверки сохранить отдельную версию, выбрать её для нового проекта.

Результат содержит объединённые столбцы и новые записи. Пропуск можно дополнить
только присутствующим значением второго источника. Непустые различающиеся
значения (включая различие типов JSON) блокируют сохранение. Точные одинаковые
дубли внутри файла исключаются; различающиеся строки с одним ключом блокируются.
При совпадении между файлами остаётся одна запись и связь с обоими источниками.
Счётчик точных дублей относится к повторам внутри каждого файла; совпадения между
файлами показаны отдельно. Конфликтные значения не перезаписываются, решение
принимается через уточнение ключей или новую документированную версию исходника.

## Присоединить характеристики

Первая база — ответы, вторая — профили с уникальным ID человека. Точное левое
соединение оставляет все строки ответов. Для повторных прохождений первой базы
нужен дополнительный ключ; во второй базе по-прежнему один профиль на человека.
Несопоставленные ответы сохраняются с пустыми добавленными характеристиками,
несопоставленные профили не превращаются в прохождения. Их количества показаны
в отчёте. Противоречие в общих непустых столбцах блокирует сохранение.

Для атрибутов, меняющихся во времени (возраст, должность и т.п.), используйте
источник соответствующего этапа; соединение по ID не подтверждает временную
совместимость. Нет автоматической проверки сопоставимости методик/версий.

## Агент и происхождение

Создать проект из результата, сохранить отбор в существующей панели, нажать
«Дать проект агенту». Ключ чтения открывает результат и прикреплённые методики.
`sourceChecks` сообщает число отобранных строк, пустые/повторные ID и коды
блокирующих причин. `readyForFormObservation` не означает готовность отправки:
видимые вопросы, варианты, отсутствующие ответы и разрешения проверяются позже.
Для повторных прохождений отбор должен оставлять уникальный ID участника в
конкретной передаче либо нужен явно согласованный иной идентификатор проекта.

В `lineage.downloadPath` агент получает историю с SHA-256 результата/родителей,
описанием источников/прав и локаторами исходных строк для каждой выходной строки.
История защищена отдельной контрольной суммой и ключом того же проекта. Доступ
к полным родительским файлам этим ключом не расширяется: они могут содержать
других участников. Первоначальное происхождение при цепочке объединений
проверяется владельцем по предыдущим версиям; автоматическое разворачивание
цепочки и проверка доказательств согласия не реализованы.

В кабинете доступны скачивание оригиналов и просмотр истории. Они требуют
выданную сессию; анонимные/чужие аккаунты закрыты. Машинный контракт команд:
`/.well-known/rrp-bank-command.schema.json`; манифест описывает права/лимиты.

## Сохранение и неизвестный результат

`bank_preview` читает файлы без записей. `bank_commit` принимает ту же `spec` и
`previewHash`, заново читает источники и вычисляет результат. Изменённый план и
конфликты блокируются. Неизменяемая атомарная резервировка допускает максимум
одну опубликованную версию на проверенный план; повтор успешного вызова возвращает
её же. При незавершённой резервировке автоматического повторного создания нет.
Перезагрузить каталог, затем разбирать состояние с владельцем. Повторное нажатие
не должно менять настройки ради обхода неопределённости. Неиндексированные файлы
после сбоя возможны; автоматического восстановления/очистки пока нет.

Не реализованы глобальный редактируемый реестр, поисковое объединение личностей,
непрерывная очередь заполнения, приглашения отдельных коллег, автоматическое
извлечение PDF/DOCX и проверенная передача фактических ответов в живую форму.
