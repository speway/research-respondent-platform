# Simulation laboratory

The authenticated cabinet saves modeled demonstration cohorts separately from
actual sources. Generation is seeded, bounded to 10–250 profiles, 1–500 attempts
and 20 generations per account per UTC day. Files persist through the existing
private Blob cabinet with checksum readback, account/environment scope and the
100-file cabinet limit. No SQLite migration, real respondent generation or Google
Forms submission is performed by this feature.

The supplied script's 39/18/11 structure is translated into a deterministic pure
TypeScript model. Six alphas are recomputed from declared scale definitions and
reverse keys. Culture stays nominal. Optional rejection sampling records its
selection condition and returns the last attempt with a false target on budget
exhaustion. This is a demo model; original instrument keys and norms have not been
verified. Reliability of a conditioned generator is not empirical validity.

Actual-source diagnostics accept named columns and a declared numeric range.
Complete cases only; missing and invalid rows are counted; negative alpha is
preserved; undefined alpha is null with a reason. Source bytes and checksum do
not change. Scale selection never infers an instrument from column count.

Agents receive separate 24-hour revocable read keys for one cohort. Such a key
cannot become a project key, read an observed bank or start/send form tasks. The
public machine schemas and /agent-simulation-lab.md explain provenance, exact
UI mapping, test accounting and receipt requirements. Existing observed-source
execution remains its separate bounded path.

The uploaded script's guessing from four/five/seven choices, random unknown
answers, clamping, force-clicks, fixed sleeps and counting Submit as success are
not adopted. Test runs need authority on the exact external form, a count and
an accounting method; provenance need not be repeated in every answer.
